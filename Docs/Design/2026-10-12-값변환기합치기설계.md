# 값 변환기 합치기 설계

> 2026-10-12 · DataTool · 결정은 8장 (사용자 확정 Q1~Q12, 바꾸지 않는다) · **구현 끝(2026-10-12)** — 설계와 달리한 것은 9장

## 0. 결론 먼저

- 「JSON 값 하나가 이 열에 맞나」를 **`internal/schema/value.go` 한 곳**에서 판정한다.
  스키마 default 검사 · validate · bake 셋이 다 이것을 부른다.
- 정답은 **지금 validate 의 칸 규칙**이다. 스키마 default 와 bake 가 거기에 맞춰진다.
- 그래서 `12.0`·`2147483648`·`1e39`·`1e-50` default 는 **스키마 검사(종료 3)** 에서 막히고,
  ref default 가 없는 id 를 가리키면 **validate(종료 2)** 가 막는다. bake 는 더는 혼자 다르게 굴지 않는다.

## 1. 왜

스칼라 값 판정이 세 벌이다. 셋이 조금씩 달라서 **validate 는 OK 인데 export 가 터지거나, 깨진 값이 조용히 구워진다.**
틈은 전부 스키마 default 쪽이다 — 칸 값은 validate 가 이미 bake 기준으로 막고 있다.

| 지금 판정하는 곳 | 함수 |
| --- | --- |
| 스키마 default | `schema/check.go` checkColumnDefault → checkValueType · checkInt · checkEnumValue |
| 칸 값 | `validate/validate.go` checkScalar · checkInt · checkFloat · checkEnum · checkRef (+ `value.go` asNumber · asString · isBool) |
| 굽기 | `bake/bake.go` convertScalar · toInt · toFloat32 · number · toBool · toString |

| 값 (default) | 스키마 검사 | validate | bake | 결과 |
| --- | --- | --- | --- | --- |
| int `12.0` · `1e3` | 통과 | 안 봄 | 오류 | validate OK · export 실패 |
| int `2147483648` | 통과 | 안 봄 | int64 로 구움 | C# int 넘침 (조용히 틀림) |
| float `1e39` | 통과 | 안 봄 | 오류 | validate OK · export 실패 |
| float `1e-50` | 통과 | 안 봄 (칸도 안 봄) | 0 으로 구움 | 조용히 틀림 |
| ref `"nope"` | 통과 | 안 봄 (asset 만 봄) | 구움 | 깨진 참조 |
| list<ref> `[""]` | 통과 | 안 봄 | 구움 | 깨진 참조 |
| enum 목록 밖 | 막음 | 막음 | **안 봄** | bake 혼자 두면 구움 |

**함정 하나** : default `12.0` + 칸 `12` 이면 `fmt`(`table/format.go` isDefault, 정규형 비교)가 칸을 지운다.
그 뒤 validate 0건 통과 → bake 가 default `12.0` 을 굽다 터진다. Q6 으로 default 자체가 종료 3 이 되니 fmt 가 칸을 지우기 전에 멈춘다.

## 2. 새 API — `internal/schema/value.go`

### 2-1. 함수

```go
// Decode 는 칸 하나(list 면 배열 통째)를 굽는 Go 값으로 바꾼다. 첫 잘못에서 멈춘다. bake 가 쓴다.
func Decode(f *File, col *Column, raw json.RawMessage) (any, error)

// DecodeItem 은 원소 하나를 col.Base 로 바꾼다. list 열이면 「list 안 빈 값」도 본다.
// 원소마다 따로 알려야 하는 쪽(스키마 default · validate)이 쓴다.
func DecodeItem(f *File, col *Column, raw json.RawMessage) (any, error)

// Items 는 list 열의 배열을 원소로 푼다. null·배열 아님은 BadList.
func Items(col *Column, raw json.RawMessage) ([]json.RawMessage, error)

// CheckBounds 는 min·max 안인지 본다. Decode 가 통과한 int·float 값에만 부른다.
func CheckBounds(col *Column, raw json.RawMessage) error

type ValueError struct {
	Kind    ValueKind
	Message string // 「파일:줄: 표.열 — 」 뒤에 붙는 부분만
}
func (e *ValueError) Error() string { return e.Message }
```

- 반환 꼴은 `(any, error)` 하나다 (Q2). 판정만 하는 곳(스키마 검사·validate)은 값을 버린다.
- 오류는 늘 `*ValueError` 다. 부르는 쪽이 `errors.As` 로 Kind 를 꺼낸다.
- `Decode` = `Items` + 원소마다 `DecodeItem`. 원소 오류는 `"%d번째 원소가 틀렸다 : %s"` 로 감싼다 (지금 bake 문구).
- `f` 는 enum 목록을 보려고 받는다 (Q5). `f.Enums[col.Enum]` 이 없으면 목록 확인을 건너뛴다 — 없는 enum 은 checkColumnEnum 이 이미 알린다.
- **CheckBounds 가 Go 값이 아니라 raw 를 받는 까닭** : float 은 Decode 가 float32 를 준다.
  `max: 0.1` 에 값 `0.1` 이면 `float32(0.1)` = 0.10000000149 라 float64 로 견주면 거짓 오류가 난다.
  지금 validate 처럼 **raw 를 float64 로 읽어 견준다.**
- 문구를 만드는 `describe` · `kindOf` · `particle` 은 validate 에서 `schema/value.go` 로 옮긴다 (안 내보냄).

### 2-2. Kind

이름이 `Column.Kind`(asset kind)와 헷갈리지 않게 타입은 `ValueKind`, 상수는 `Bad*` 로 쓴다.

| Kind | 상수 | 뜻 | 예 |
| --- | --- | --- | --- |
| type | `BadType` | 타입이 아니다 | int 열에 `"12"` · bool 열에 `1` |
| form | `BadForm` | 값은 맞는데 적은 꼴이 틀렸다 | int 열에 `12.0` · `1e3` |
| range | `BadRange` | **타입이 못 담는다** (int32 · float32) | `2147483648` · `1e39` · `1e-50` |
| enum | `BadEnum` | enum 목록 밖 | `"legend"` |
| null | `BadNull` | null 은 값이 아니다 | `null` |
| list | `BadList` | 배열이 아니다 · list<ref>/list<asset> 안에 `""` | `"a"` · `[""]` |

> **range 는 min·max 가 아니다.** min·max 는 열 규칙이라 `CheckBounds` 가 따로 본다 (Q4). 그 오류도 `*ValueError` 이고 Kind 는 `BadRange` 지만 부르는 쪽은 Kind 를 보지 않는다 — 부른 자리가 곧 V4 다.
> 수가 아닌 raw 로 `CheckBounds` 를 잘못 부르면 Kind `BadType` 을 준다 (구현 때 더함).

### 2-3. 타입별 판정 (validate 칸 규칙이 정답)

| Base | 받는 꼴 | 거절 (Kind) | 결과 Go 타입 |
| --- | --- | --- | --- |
| int | JSON 수 + 글자가 `^-?[0-9]+$` + int32 안 | 수 아님 type · 소수 꼴 form · int32 밖 range | `int64` (지금 bake 와 같다 · mpack 바이트 그대로) |
| float | JSON 수 + float32 안 + 아래넘침 아님 | 수 아님 type · `\|v\|>MaxFloat32` range · **0 아닌데 float32 로 0** range (Q10) | `float32` |
| bool | `true` · `false` | 그 밖 type | `bool` |
| string | JSON 문자열 (`""` 됨) | 그 밖 type | `string` |
| enum | 문자열 + 목록 안 | 문자열 아님 type · 목록 밖 enum | `string` |
| ref · asset | JSON 문자열 | 그 밖 type · **list 열일 때만** `""` list | `string` |
| list<T> | 배열, 원소마다 위 규칙 | null · 배열 아님 list | `[]any` |
| 공통 | — | 값 자리 `null` → null (list 원소도) | — |

- 판정 차례 : null → 타입 → 꼴 → 범위 → 목록. 앞에서 걸리면 뒤는 안 본다.
- **`""` 를 막는 것은 list<ref> · list<asset> 의 원소뿐이다.** list<string> 의 `""` 는 받는다. 스칼라 ref·asset 의 `""` 는 「없음」이라 받는다 — 필수 열인지는 Decode 밖(validate)이 본다.
- float 아래넘침 : `strconv.ParseFloat(s, 32)` 는 1e-50 을 오류 없이 0 으로 준다. 그래서 「float64 로는 0 이 아닌데 float32 로 0」을 따로 잡는다. 1e-40 같은 비정규수는 0 이 아니라 받는다.

### 2-4. 문구

validate 의 문구를 정본으로 쓴다. 설계 때 바뀌는 것은 두 줄이었고, 구현하며 두 줄(int 지수 꼴 · CheckBounds 잘못 부름)을 더했다.
float 범위는 raw 글자가 아니라 `strconv.ParseFloat` 결과로 판정한다 — 그래야 `1e±400` 도 잡는다 (리뷰 ①).

| Kind | 문구 |
| --- | --- |
| type | `int 가 와야 하는데 문자열 "12" 다` (지금 validate addType 그대로) |
| form | `int 열인데 소수 꼴로 적혔다: 12.0 (소수점 없이 적는다)` · 값도 소수면 `int 열인데 소수다: 12.5` |
| form int 지수 꼴 | **새로** `int 열인데 지수 꼴로 적혔다: 1e3 (자릿수를 다 적는다)` · int `1e400` 도 type 이 아니라 이 form 이다 |
| range int | `int 가 담을 수 있는 범위를 넘었다: 2147483648 (C# int 는 32비트다)` |
| range float | **바뀜** `float32 로 담을 수 없다: 1e39 (C# float 은 32비트다)` — bake 시험(:301)의 낱말을 살린다. float64 로도 못 담는 `1e400` 도 같은 문구 |
| range float 아래 | **새로** `float32 로 담으면 0 이 된다: 1e-50 (0 이면 0 으로 적는다)` · `1e-400` 도 잡는다 |
| CheckBounds 잘못 부름 | **새로** (Kind `BadType`) `min·max 는 수에만 견준다: 문자열 "5"` |
| enum | `enum Grade 에 없는 값이다: "legend" (있는 것: …)` |
| null | `int 가 와야 하는데 널 null 다` (지금 validate 그대로 — addType 꼴) |
| list | `list<int> 열인데 배열이 아니다: …` · `list<ref> 안에 빈 id 가 있다 (빼거나 id 를 적는다)` · `list<asset> 안에 빈 주소가 있다 (빼거나 주소를 적는다)` |

## 3. 호출자별 바뀌는 것

### 3-1. 스키마 검사 (`schema/check.go`)

| 항목 | 내용 |
| --- | --- |
| 지우는 것 | checkValueType · checkInt · checkEnumValue (isNullValue 는 Items·Decode 안으로) |
| 새로 부르는 자리 | checkColumnDefault : list 면 `Items` → 원소마다 `DecodeItem`, 아니면 `DecodeItem`. 통과하면 `CheckBounds` |
| 오류 매핑 | Kind 는 안 본다. `c.add(where, err.Error())` 한 줄 |
| 종료 코드 | 3 (`*schema.Errors`) |
| 자리 | `tables[i].columns[j].default` · 원소는 `…default[k]` (지금과 같다) |

- CheckBounds 는 min ≤ max 이고 Base 가 int·float 일 때만 부른다 — 아니면 checkColumnBounds 가 이미 알렸다.
- default 에 `null` 은 `Items`/`DecodeItem` 이 BadNull · BadList 로 막는다. 지금 문구 「기본값이 null 이다 (…)」는 checkColumnDefault 앞머리에 그대로 둔다 (default-null 시험 자리 유지).

### 3-2. validate (`validate/validate.go` · `value.go` · `asset.go`)

| 항목 | 내용 |
| --- | --- |
| 지우는 것 | checkInt · checkFloat · asNumber · isBool · isNull · intForm · describe · kindOf · particle · addType |
| 남는 것 | asString (hasEmptyID 의 id 칸만) · checkBounds 자리 → `schema.CheckBounds` 를 부르는 얇은 줄 · checkRef · checkAsset 은 남되 **인자가 raw 에서 `v string` 으로** 바뀐다 (DecodeItem 이 준 값을 그대로 받는다, 다시 파싱 안 함 — 리뷰 ③) |
| 새로 부르는 자리 | checkList : `schema.Items`. checkScalar : 모든 Base 에서 먼저 `schema.DecodeItem` → 통과하면 Base 별 뒤 일 (int·float 는 CheckBounds, ref 는 id 존재, asset 은 V10 색인) |
| 오류 매핑 | 아래 표 |
| 종료 코드 | 2 (지금과 같다) |
| 자리 | `파일:줄: 표.열` · 원소는 `열[k]` (지금과 같다) |

| Kind | Rule | 비고 |
| --- | --- | --- |
| type · form · range · null | `RuleType` (V3) | v3-null · v3-int-form · v3-float32 시험이 이것을 기대한다 |
| enum | `RuleEnum` (V5) | |
| list (배열 아님) | `RuleList` (V9) | |
| list (원소 `""`) | ref 열 `RuleRef` (V6) · asset 열 `RuleAsset` 을 `v10` 으로 | **Base 로 갈라 지금 Rule 을 지킨다.** asset 은 serve 저장 때 경고로 가는 길도 그대로 |
| CheckBounds 오류 | `RuleRange` (V4) | Kind 와 상관없이 부른 자리로 정한다 |

**빈 값 규칙은 Decode 밖, validate 에 남는다.**

| 경우 | 어디서 | 결과 |
| --- | --- | --- |
| 칸이 없다 · 필수 열 | checkColumns (지금 그대로) | V2 `RuleRequired` |
| 스칼라 ref·asset `""` · 선택 열 | checkRef · checkAsset (Decode 통과 뒤) | 통과 (「없음」) |
| 스칼라 ref·asset `""` · 필수 열 | checkRef · checkAsset | V2 `RuleRequired` |
| list<ref>·list<asset> 안 `""` | **DecodeItem 안** (BadList) | 위 표대로 V6 · V10 |

### 3-3. bake (`bake/bake.go`)

| 항목 | 내용 |
| --- | --- |
| 지우는 것 | convert · convertScalar · toInt · toFloat32 · number · toBool · toString · isNull · shorten |
| 새로 부르는 자리 | bakeCell : `schema.Decode(sch, col, raw)`. 이를 위해 `bakeTable(sch, def, t)` 로 스키마를 넘긴다 |
| 오류 매핑 | Kind 는 안 본다. `cellError(…, err.Error())` — Message 만 (Q3) |
| 종료 코드 | 2 (지금과 같다) |
| 자리 | `파일:줄: 표.열` (bake.Error, 지금과 같다) · default 로 채운 칸도 그 행 자리 |

- 이제 bake 도 enum 목록 밖 값, int32 밖 int, float32 아래넘침을 굽지 않는다.
- 결과 Go 타입이 지금과 같아(int64·float32·bool·string·[]any) **맞는 데이터면 구운 바이트가 한 바이트도 안 바뀐다.**

## 4. default 검사 흐름

```text
schema.Load / schema.Parse         (종료 3 · 자리 tables[i].columns[j].default)
  └ checkColumnDefault : 꼴 — 타입·꼴·int32/float32·null·enum 목록·list 배열·list 안 ""
                        + CheckBounds (min·max)
validate.RunWith                   (종료 2 · 자리 schema.json:0: 표.열.default)
  └ checkDefaults (← checkAssetDefaults 이름 바꿈)
       ref · list<ref>    : 가리키는 id 가 있나 (V6)
       asset · list<asset>: 색인에 있나·kind·빌드 (V10, 지금과 같다)
```

| 물음 | 어디서 | 왜 |
| --- | --- | --- |
| 값이 타입·꼴에 맞나 | 스키마 검사 (3) | 데이터 없이 스키마만 보고 알 수 있다. fmt·serve 도 이 단계에서 멈춘다 |
| list<ref> `[""]` | 스키마 검사 (3) | 꼴 규칙이다 (Q8) |
| min·max 안인가 | 스키마 검사 (3) | 스키마 안의 두 칸끼리 비교다 (Q4) |
| ref default 의 id 가 있나 | validate (2) | 데이터 표를 읽어야 안다 (Q7) |
| asset default 가 색인에 있나 | validate (2) | 색인을 읽어야 안다 (지금 그대로) |

- 차례 : 스키마 검사가 통과해야 validate 가 돈다. 그래서 checkDefaults 는 **꼴이 맞다고 믿고 존재만 본다.** 꼴 오류가 두 번 나지 않는다.
- checkDefaults 는 ref·asset 열(`TypeAsset || TypeRef`)마다 **`Decode` 를 한 번 부르고, 원소마다 checkRef·checkAsset 으로 존재만 본다** (전용 고리 `checkDefault`). 설계 때 적은 「`spot` checker 로 `checkValue` 를 돈다」는 꼴 검사를 한 번 더 도는 것이라 바꿨다 (리뷰 ④).
- 스칼라 ref default `""` 는 받는다 (default 가 있으니 필수 열이 아니다 → 「없음」).
- default 문제를 칸 문제 앞에 두는 것(잘림에 안 잘림)은 그대로다.
- serve 의 스키마 저장(`serve/schema_edit.go` planEdit)도 `schema.Parse` → `validateForSave` 를 거치므로 **웹에서 고친 default 도 같은 두 단계에 걸린다.** 따로 할 일은 없다.
