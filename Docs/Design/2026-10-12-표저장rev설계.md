# 표 저장 rev 설계 — 디스크가 바뀌었으면 덮지 않는다 (1판 · 2판)

입력 : 스키마 저장의 rev 틀 `2026-10-04-스키마Enum편집설계.md` 3장·4장·7장「rev 의 바탕」 · `internal/serve/schema_edit.go` · `ui/schema.js` 저장 흐름 · U6 K4.
결정 : 사용자 확정 2026-10-12 (Q1~Q9, 8장).
상태 : **구현 끝(2026-10-12)** — 시험 327 → 332 통과 · vet 깨끗 · U6 36 → 42/42 · 리뷰 8건 중 6건 반영. 구현하며 정한 것·리뷰 반영·알려진 빈틈은 9장.
**2판 끝(2026-10-12 저녁)** — 표 PUT 이 스키마 rev 도 본다(`X-Schema-Rev`, 고른 머리) · 스키마 PUT 도 쓴 바이트 rev. 시험 339 · U6 48/48. 9-3.

## 0. 결론

- **표 PUT 도 스키마 PUT 처럼 rev + If-Match + 409 로 막는다.** rev 는 표 파일 디스크 바이트의 sha256 hex 64자다.
- GET `/api/table/x` 가 rev 를 주고, 웹은 그것을 `state.rev` 로 들고 있다가 PUT 의 `If-Match` 에 싣는다.
  디스크가 그사이 바뀌었으면 서버는 **아무것도 안 쓰고** 409 를 준다. 웹은 빨간 토스트에 「다시 읽기」 단추를 띄운다.
- 저장이 되면 200 에 **쓴 바이트의 새 rev** 를 실어 준다. 그래야 다음 저장이 자기 저장 때문에 409 가 안 난다.
- 웹 `save()` 에 **진행 중 막기**(`state.saving`)와 **편집 세대 번호**(`state.editGen`)를 더한다. Ctrl+S 연타와 「저장 중 편집이 dirty 를 잃는」 옛 버그를 같이 고친다.
- 강제 덮어쓰기 길은 없다. 스키마 rev 는 1판에서 안 봤고, **2판에서 고른 머리 `X-Schema-Rev` 로 본다** (9-3).

## 1. 왜

지금 표 PUT(`internal/serve/api.go` putTable)은 디스크의 스키마·표를 새로 읽지만 **보던 판과 견주지 않는다.**
웹에서 표를 열어 둔 사이 다른 사람·편집기·git 이 item.json 을 고쳐도, 웹에서 저장하면 그 변경이 말없이 사라진다.
스키마 저장에는 이미 같은 막기(rev)가 있고 U6 K4 로 실측했다. 그 틀을 표에 그대로 얹는다.

### 2-2. GET `/api/table/{이름}`

| 상태 | 본문 |
| --- | --- |
| 200 | `{ok:true, name, columns, rows, rev, schemaRev}` — 1판은 rev 만 더했고, 2판이 `schemaRev`(= GET /api/schema 의 rev)를 더한다 |
| 400 · 404 | 지금과 같다 |

- s.mu 안에서 `raw, rev := fileRev(path)` 한 번 읽고, 행은 `table.Parse(textfile.TrimBOM(raw), path)` 로 **같은 바이트**에서 낸다.
  지금처럼 `table.Load` 로 따로 읽으면 rev 와 행이 서로 다른 판일 수 있다.
- 목록 API(`GET /api/tables`)에는 rev 를 안 넣는다 (Q2).

### 2-3. PUT `/api/table/{이름}`

요청 : 머리 `Content-Type: application/json` · `If-Match: <GET 이 준 rev>` (따옴표로 싸도 된다 — 스키마와 같이 `strings.Trim(want, "\"")`). 본문은 지금처럼 행 배열.
2판 : 고른 머리 `X-Schema-Rev: <GET 이 준 schemaRev>`. If-Match 와 같은 `revHeader` 로 걷는다(`W/`·따옴표 뗌). 없거나 `*` 면 스키마 rev 를 안 본다 — If-Match 만 싣는 옛 스크립트가 안 깨지게.

| 상태 | 언제 | 본문 |
| --- | --- | --- |
| 200 | 썼다 (또는 같은 바이트라 안 썼다) | `{ok:true, name, rows, path, warnings, rev, schemaRev}` — rev 는 **쓴 바이트**의 rev |
| 400 | 본문·이름이 잘못 · 검증에 걸림 · 파일 읽기 실패 | 지금과 같다 |
| 404 | 스키마에 없는 표 | 지금과 같다 |
| 405 · 415 | 지금과 같다 | 지금과 같다 |
| **428** | If-Match 가 없거나 비었다 | `{ok:false, error:"If-Match 머리에 GET /api/table/<표> 의 rev 를 실어 보낸다"}` |
| **409** | If-Match ≠ 지금 디스크 rev | `{ok:false, conflict:"table", rev:<지금 디스크 rev>, schemaRev, error:"그사이 <표>.json 이 바뀌었다 — 다시 읽고 고친다"}` · **아무것도 안 쓴다** |
| **409** (2판) | `X-Schema-Rev` 를 실었고 ≠ 지금 schema.json rev | `{ok:false, conflict:"schema", rev, schemaRev, error:"그사이 schema.json 이 바뀌었다 — 다시 읽고 고친다"}` · 안 쓴다 |
| 500 | 쓰기 실패 | 지금과 같다 |

### 2-4. PUT 안의 차례

| # | 할 일 | 걸리면 |
| --- | --- | --- |
2판(9-3) 기준이다. 굵은 줄이 2판에서 바뀐 자리다.

| # | 할 일 | 걸리면 |
| --- | --- | --- |
| 1 | Content-Type | 415 |
| 2 | If-Match 있나 | 428 |
| 3 | 본문 행 배열 읽기 (readRows) · `X-Schema-Rev` 걷기 (`revHeader`) | 400 |
| 4 | **s.mu 잡기** | — |
| 5 | **`readSchema`(schema.json 한 번 읽어 파싱 + rev) · `LoadAllExcept`(이 표는 안 읽음)** · 스키마에 표 있나 · tablePath | 400 · 404 |
| 6 | `raw, rev := fileRev(path)` → If-Match 와 견줌 | 409 `conflict:"table"` |
| 7 | **`X-Schema-Rev` 를 실었으면 schema.json rev 와 견줌** | 409 `conflict:"schema"` |
| 8 | parseRows(받은 행) · validateForSave | 400 |
| 9 | `out := t.Format(st)` | 400 |
| 10 | `bytes.Equal(out, raw)` 면 안 쓰고 rev 그대로 (Q8). 아니면 `table.WriteFile` | 500 |
| 11 | 200 · `rev: revOf(out)` · `schemaRev` | — |

- 6·7번을 검증(8번)보다 앞에 둔다 — 낡은 판으로 검증 오류를 보여 줘 봤자 쓸모없다 (Q3).
- 6번이 5번 뒤인 까닭 : 지금의 404·400(파일 없음) 판정을 그대로 두기 위해서다. `LoadAllExcept` 도 이 표 파일이 **있는지**는 본다.
- **디스크 표 파일이 깨졌으면 409 다.** 디스크 표는 파싱하지 않고 rev 만 견준다. 깨진 파일은 GET 이 400 이라 클라이언트가 그 rev 를 가질 수 없으니 늘 6번에 걸린다 (1판은 loadAll 이 먼저 파싱해 400 이었다 — `TestPutTableBrokenDiskIs409`).
- 응답 쓰기는 잠금 밖이다. `saveTable` 이 잠금 안에서 (code, body) 만 만들고 `putTable` 이 밖에서 쓴다 (GET 도 `readTable` 로 같은 꼴).
- **11번은 다시 읽지 않고 `out` 을 해시한다.** 스키마 PUT 은 쓴 뒤 다시 읽는데, 그러면 쓰기와 다시 읽기 사이에 밖에서 고친 것이 새 rev 에 섞여 다음 저장이 그것을 덮는다. 표는 그 틈을 안 만든다 (스키마 쪽은 2판에서 같게 고침, 9-3).

## 3. 웹이 할 일 (`ui/app.js`)

| 무엇 | 어떻게 |
| --- | --- |
| rev 들기 | `state.rev = ""` 더함. `openTable` 이 GET 성공 때만 `state.rev = res.body.rev`. 실패하면 옛 표·옛 rev 그대로 |
| loadRefIDs 분리 | ref 표 GET 응답은 `state.ids` 만 채운다. **`state.rev` 에 손대지 않는다.** 주석으로 박아 둔다 |
| PUT 머리 | `headers: {"Content-Type": ..., "If-Match": state.rev}` |
| 진행 중 막기 | `save()` 맨 앞 `if (state.saving) return;` (말없이 무시). `state.saving = true` → `finally` 에서 false |
| 편집 세대 | `state.editGen = 0`. `setDirty(true)` 가 불릴 때마다 `editGen++`. save 는 행을 뜨기 직전 `gen = state.editGen` 을 적어 둔다 |
| 성공 | 응답 때 보던 표가 그대로인지(`state.grid === grid` 로 견줌) 보고, 그렇다면 `state.rev = res.body.rev`. **`state.editGen === gen` 일 때만** `setDirty(false)`. 다르면 dirty 를 켠 채 둔다 |
| 409 | `res.status === 409` 로 판단한다 (body.ok 만 보지 않는다). dirty 그대로 · `state.rev` 는 **안 바꾼다** (바꾸면 다음 저장이 그냥 덮는다) |
| 409 토스트 | 빨간 토스트 「그사이 디스크의 <표>.json 이 바뀌었다 — 아무것도 안 썼다. 「다시 읽기」 는 고친 것을 버리고 디스크 것을 읽는다」 + 단추 「다시 읽기」(id `toastReload`). 고친 것을 살리려면 칸을 복사해 뒀다가 다시 읽은 뒤 붙여 넣으라는 글을 한 줄 붙인다 (Q6) |
| 「다시 읽기」 | confirm 없이 `setDirty(false)` → `openTable(state.name)` |
| 428 | 웹이 늘 머리를 실으니 정상 길에선 안 난다. 나면 error 글을 빨간 토스트로 (지금 실패 길) |

**토스트 손질** : 지금 `toast()` 는 `textContent` 만 쓴다. 단추를 달 수 있게 `toast(message, bad, action)` 처럼 고른 칸을 더하고, 단추가 있는 토스트는 **저절로 안 사라진다**(다음 토스트나 단추 누름에 닫힘). 6초 만에 사라지면 「다시 읽기」를 놓친다.
`textContent` 를 읽는 U6 도우미(waitToast)는 단추 글까지 읽힌다 — 판정은 `includes` 로 하니 괜찮다.

## 9. 구현하며 정한 것 (2026-10-12)

새 파일 `internal/serve/rev.go` 에 `fileRev` · `revOf` · `ifMatchRev` 를 둔다.
GET 은 잠금 안에서 표 파일을 한 번 읽고 같은 바이트로 Parse 한다. `loadSchema` 도 잠금 안에서 한다.
1판 PUT 차례는 415 → 428 → 본문 → 잠금 → loadAll·404 → 409 → 검증 → Format → 같은 바이트면 안 씀 → 200 에 쓴 바이트의 rev 였다. 2판 차례는 2-4 표다.

설계 밖에서 정한 세부 :

| 무엇 | 정한 것 | 까닭 |
| --- | --- | --- |
| save / saveTable 나누기 | `save()` 는 진행 중 막기·세대 적기만, 실제 PUT 과 응답 처리는 `saveTable()` | 막기와 저장 흐름이 섞이지 않게 |
| 저장 때 이름 쓰기 | 토스트 글과 `ids.delete` 에 **저장을 시작할 때 잡아 둔 표 이름**을 쓴다 | 응답 전에 딴 표로 옮겨도 엉뚱한 이름이 안 나오게 |
| 409 토스트 | 보던 표가 바뀌었어도 **늘 띄운다** | 「아무것도 안 썼다」는 사실은 표를 옮겨도 알려야 한다 |

3장과 달라진 것 : `If-Match` 는 `W/` 접두와 따옴표를 걷고 견준다. `*` 는 없는 것과 같게 428 이다.
「다시 읽기」 는 `openTable(이름, { skipConfirm: true })` 로 confirm 없이 부르고, dirty 는 **읽기가 성공해야** 꺼진다 (3장의 「먼저 `setDirty(false)`」 를 바꿈 — 리뷰 1).

### 9-1. 리뷰 반영 (코드 리뷰 high, 8건 중 6건)

| # | 지적 | 고친 것 |
| --- | --- | --- |
| 1 | 「다시 읽기」 가 dirty 를 먼저 꺼서, 읽기가 실패하면 편집을 잃는다 | `skipConfirm` 인자로 confirm 만 건너뛰고, dirty 는 openTable 성공 때 끔 |
| 2 | 낡은 토스트의 「다시 읽기」 가 지금 보는 다른 표를 되읽는다 | 토스트가 표 이름을 잡아 두고, 지금 표와 다르면 아무것도 안 함. openTable 이 성공하면 토스트를 닫음 |
| 3 | `If-Match` 의 `W/` · `*` 처리 | `ifMatchRev` 가 `W/`·따옴표를 걷고 `*` 는 428 |
| 4 | 늦게 온 응답이 다른 표의 문제 목록을 덮는다 | 응답 때 grid 가 같을 때만 rev·dirty·문제 목록·칸 표시를 만짐 |
| 5 | 시험이 기대 rev(정답)를 서버와 같은 길로 내야 한다 | 시험의 기대 rev 도 `fileRev` 로 냄 |
