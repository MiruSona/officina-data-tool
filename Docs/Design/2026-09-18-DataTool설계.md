# DataTool 설계 — 폴더·데이터 꼴·스키마·CLI·내보내기·표 UI

설계일 : 2026-09-18
전제 (사용자 확정) : 이름 `DataTool` · Go 단일 exe + 내장 웹 표 UI · 원본 JSON · 런타임 MessagePack ·
1차는 표 편집·검증·Unity 내보내기, 암호화와 엑셀 가져오기는 2차.
근거 : `Research/2026-09-18-데이터관리툴조사.md` 와 그 아래 세 상세 문서.
안 한 것 : 코드를 한 줄도 안 썼다. Go 도 Unity 도 안 돌렸다. 성능을 안 쟀다.

## 0. 결론 먼저

| 물음 | 정한 것 |
| --- | --- |
| 폴더 | `DataTool/` 안에 `cmd/datatool` · `internal/…` · `ui/` · `Unity/` · `Testdata/` · `Docs/`. 자기완결 |
| 데이터 원본 | `GameData/<표>.json` — **진짜 JSON 배열인데 행 하나가 한 줄**. `[` 와 `]` 만 따로 선다 |
| id | **문자열**, 표 안에서 유일, `^[a-z][a-z0-9_]*$`. 번호를 다시 매기는 일이 없다 |
| 스키마 | **`GameData/schema.json` 한 파일** (C안). 사람이 보게 들여쓴다 — 데이터 파일과 반대 규칙 |
| 타입 | `int` · `float` · `bool` · `string` · `enum` · `ref` · `list<…>` **일곱**. 그 이상 안 만든다 (2026-10-01 연동 설계로 `asset` 을 더해 **여덟**) |
| 조사 결론 뒤집기 | 스키마를 C# 코드가 아니라 **DataTool 이 갖는다.** Go 가 못 읽으면 검증·굽기·코드 생성이 아예 안 된다 |
| CLI | `init` · `fmt` · `validate` · `export` · `gen` · `serve` · `version` **일곱**. 전부 `--json` 을 받는다 |
| 굽는 파일 | `gamedata.bytes` 한 장. **16바이트 머리 + MessagePack 본문.** 머리에 암호화 자리를 비워 둔다 |
| MessagePack | **직접 쓴다** (`internal/mpack`). 내보내는 꼴이 일곱뿐이라 라이브러리 값이 없다. 최종 판단은 메인 몫 |
| C# 생성 | `[MessagePackObject]` + `[Key(n)]`, n 은 **열 차례**. 굽는 쪽도 배열로 써서 짝을 맞춘다 |
| 표 UI | **Tabulator** (MIT · 7.8k · 2026-09-15). 빌드 단계가 없어 `.js`·`.css` 를 그대로 `go:embed` 한다 |
| 저장 | UI 는 JSON 을 절대 안 만든다. **행 배열을 엔진에 넘기면 엔진이 검증하고 파일을 쓴다** |

## 2. 폴더·파일 모양

```
DataTool/
├─ go.mod                     ← 바깥 라이브러리 0개 · CGO_ENABLED=0
├─ cmd/datatool/main.go       ← 인자 가르기만. 일은 internal 이 한다
├─ internal/
│  ├─ schema/   스키마 읽기·검사 (타입 목록이 여기 하나뿐이다)
│  ├─ table/    데이터 JSON 읽기·쓰기 (한 줄 한 행 규칙을 아는 유일한 곳)
│  ├─ validate/ 검증 규칙 (6장)   ├─ mpack/ MessagePack 인코더(+시험용 디코더)
│  ├─ bake/     머리+본문 조립    ├─ gen/   C# 생성      └─ serve/ 로컬 서버·API
├─ ui/          index.html · app.js · app.css · vendor/tabulator.min.{js,css}   ← go:embed
├─ Unity/       Officina.Data.asmdef · GameDataLoader.cs  ← 게임이 복사해 가는 손으로 쓴 C#
├─ Testdata/    작은 표 3개 + 일부러 깨뜨린 판
└─ Docs/{Research,Design,Todo,History}/
```

게임 프로젝트 쪽 :

```
<게임>/
├─ GameData/                      ← 원본. git 에 커밋된다
│  ├─ schema.json · item.json · monster.json · drop.json
│  └─ .datatool.json              ← 내보내기 자리·네임스페이스를 적은 작은 설정
└─ Assets/
   ├─ _Project/Scripts/Data/Generated/   ← datatool gen 산출물. 손대지 않는다
   └─ StreamingAssets/gamedata.bytes     ← datatool export 산출물
```

`GameData/` 를 `Assets/` 밖에 두는 이유 : Unity 가 원본 JSON 을 임포트할 이유가 없고 표마다 `.meta` 가 붙어
diff 가 지저분해진다. 옮기고 싶으면 `.datatool.json` 으로 바꾼다.

**다른 툴 폴더를 가리키는 경로를 두지 않는다.** 네임스페이스 치환은 CodeTool 과 같은 방식을 쓰되
스크립트를 공유하지 않고 DataTool 이 자기 것을 갖는다 (규칙 11번).

## 3. 데이터 원본 꼴

`GameData/item.json` :

```json
[
{"id":"sword_iron","name":"철검","atk":12,"price":300,"grade":"common","tags":["weapon","melee"]},
{"id":"potion_hp","name":"체력 물약","price":50,"grade":"common","tags":["consume"]}
]
```

규칙 넷.

1. **파일 전체가 유효한 JSON 배열이다.** JSON Lines 를 안 쓴 이유가 이것 — Go 의 `encoding/json`,
   브라우저, AI 가 손대지 않고 그냥 읽는다. 「우리 툴이 있어야 읽히는 형식」을 만들지 않는다.
2. **행 하나가 한 줄이다.** `[` 와 `]` 만 자기 줄에 선다. git diff 가 「몇 번 아이템이 어떻게 바뀌었나」로 읽힌다.
3. **열 차례는 스키마 차례를 따른다.** 툴이 늘 그 차례로 쓰므로 값을 안 고치면 줄이 안 흔들린다.
4. **기본값이면 열을 뺀다** (위 `potion_hp` 의 `atk`). 줄이 짧아지고 기본값을 바꾸면 한 번에 따라온다.

파일 이름은 **표 이름 그대로**, 소문자 한 낱말. 파일 이름과 스키마의 표 이름이 다르면 검증에서 막는다.

**id 는 문자열이다.** 숫자 id 는 행을 지우면 번호를 다시 매기게 되고 그러면 참조가 **조용히 어긋난다.**
문자열이면 diff 에서 `sword_iron` 으로 읽히고, 없는 id 를 가리키면 검증이 바로 잡는다.
`ref` 열은 그 문자열을 그대로 담는다.

**다국어는 1차에 그냥 `string` 열**이다. 한국어를 그대로 넣는다. 대신 문 하나만 열어 둔다 —
스키마의 열에 `"loc": true` 를 달 수 있게 하고 **1차에서는 검증·굽기가 이 표시를 무시한다.**
2차에 이 표시가 붙은 열만 골라 Unity Localization 의 String Table 로 뽑으면 된다.
나중에 데이터를 다시 훑어 「어느 열이 번역 대상이었나」를 사람이 찍는 일이 없어진다.

## 4. 스키마 꼴

### 4-1. 왜 DataTool 이 스키마를 갖나 (조사 결론을 뒤집는다)

조사 문서는 「스키마는 C# 코드에 둔다」(BakingSheet 방식)고 했다. **1차에서 뒤집는다.**

- 검증·굽기·코드 생성을 하는 것은 **Go 엔진**이다. 스키마가 C# 소스에 있으면 Go 가 C# 을 파싱해야 한다 —
  그건 툴을 하나 더 만드는 일이다.
- 「설정은 코드에 둔다」(규칙 10번)와 안 부딪힌다. **C# 클래스를 툴이 생성**하므로 게임 코드엔 여전히
  타입이 있는 코드가 있고 인스펙터 배선은 어디에도 안 생긴다. Luban·CastleDB·Charon 이 전부 이 방향이다.
- 스키마 파일은 **사람이 읽는 작은 텍스트**다. AI 가 그대로 읽고 고친다.

### 4-2. 어디에 둘까 — 세 안

| 안 | 모양 | 좋은 점 | 나쁜 점 |
| --- | --- | --- | --- |
| A | 각 표 JSON **첫 줄에** 얹는다 (CastleDB 식) | 표가 자기 설명을 갖는다 | 「한 줄 한 행」이 거짓이 된다. 읽는 모든 코드가 첫 줄을 특별 취급한다 |
| B | 표마다 `item.schema.json` | 표와 정의가 나란히 있다 | 파일이 두 배. **참조 관계를 한눈에 못 본다.** 굽는 차례를 따로 정해야 한다 |
| **C** | **`schema.json` 한 파일** | 참조 그물이 한 화면에. 굽는 차례 = 적힌 차례. 엔진이 파일 하나만 읽으면 다 안다 | 표가 수십 개면 길어진다. 동시 편집 충돌 |

**C 를 고른다.** 나쁜 점 둘이 지금 조건에서 안 아프다 — 표가 수십 개가 되면 그때 B 로 쪼개도
**파일만 나누면 되는 일**이고(엔진은 합쳐 들고 있다), 동시 편집 충돌은 1인 개발에 없다.
반대로 C 가 주는 「참조 그물을 한눈에」는 검증과 코드 생성 양쪽에서 매번 쓰인다.

### 4-3. 꼴과 타입

```json
{ "version": 1, "namespace": "MyGame.Data",
  "enums": { "Grade": ["common", "rare", "epic"] },
  "tables": [
    { "name": "item", "columns": [
      { "name": "id",    "type": "string" },
      { "name": "name",  "type": "string", "loc": true },
      { "name": "atk",   "type": "int",   "min": 0, "max": 9999, "default": 0 },
      { "name": "grade", "type": "enum",  "enum": "Grade", "default": "common" },
      { "name": "tags",  "type": "list<string>" } ] },
    { "name": "drop", "columns": [
      { "name": "id",     "type": "string" },
      { "name": "itemId", "type": "ref",   "ref": "item" },
      { "name": "rate",   "type": "float", "min": 0, "max": 1 } ] } ] }
```

- **첫 열은 반드시 `id`, 타입 `string`이다.** 예외를 안 만든다.
- 열 칸은 `name`·`type`·`default`·`min`·`max`·`enum`·`ref`·`loc`·`desc`·`kind` **열**이 전부다. `kind` 는 `asset` 열에만 단다 (연동 설계 3-1).
- `default` 가 없고 값도 없으면 **필수 열**이다. `required` 칸을 따로 안 만든다 — 칸을 줄이고,
  기본값 있는 열을 빈 채로 두는 실수도 같이 막는다.

| 타입 | JSON | C# | 비고 |
| --- | --- | --- | --- |
| `int` / `float` / `bool` | 숫자·참거짓 | `int` / `float` / `bool` | float 은 굽을 때 float32 |
| `string` | 문자열 | `string` | `loc` 표시 가능 |
| `enum` | 목록 안의 문자열 | 생성된 `enum` | `enum` 칸 필수 |
| `ref` | 다른 표의 id | `string` | 로더가 딕셔너리로 이어 준다 |
| `asset` | Addressables 주소 문자열 | `string` | 검증 V10 은 AssetTool 색인으로 본다 (연동 설계 3-3) |
| `list<T>` | 배열 | `T[]` | `T` 는 위 일곱 중 하나. **중첩 list 는 안 된다** |

없는 것 : 날짜·시간·벡터·중첩 문서·수식. **필요해지면 표를 하나 더 만든다**로 푼다.

## 5. CLI

```
datatool <명령> [--data DIR] [--json] [옵션…]
```

`--data` 는 `GameData/` 다. 안 주면 지금 폴더에서 위로 올라가며 `.datatool.json` 을 찾는다.

| 명령 | 하는 일 | 쓰나 |
| --- | --- | --- |
| `init` | 빈 `schema.json`·`.datatool.json`·예제 표 한 장 | **쓴다** (있으면 건너뜀) |
| `fmt` | 데이터 JSON 을 규칙대로 다시 쓴다 (열 차례·한 줄 한 행·기본값 빼기) | **쓴다** |
| `validate` | 6장의 규칙을 다 돌린다 | 안 쓴다 |
| `export` | `gamedata.bytes` 를 굽는다. 먼저 `validate` | **쓴다** (`-o` 자리 하나) |
| `gen` | C# 을 만든다. 먼저 `validate` | **쓴다** (생성 폴더 안만) |
| `serve` | 표 UI 를 띄운다 | **쓴다** (UI 가 저장할 때만) |
| `version` | 판·빌드 시각 | 안 쓴다 |

원본 JSON 을 고치는 것은 `fmt` 와 `serve` 뿐이다.
**`--force` 같은 우회 옵션을 만들지 않는다** (`security-invariants` 2번) — 굽기를 억지로 통과시키는 문을
열면 그 문이 기본값이 된다.

| 종료 코드 | 뜻 |
| --- | --- |
| 0 / 1 | 성공 / 사용법 잘못 |
| **2** | **데이터 검증 실패** (타입·필수·참조·중복·범위) |
| **3** | **스키마 자체가 틀림** (모르는 타입, 없는 enum, 첫 열이 id 가 아님) |
| 4 / 5 | 읽기 실패 (없음·JSON 깨짐·경로 감옥) / 쓰기 실패 |

2 와 3 을 가르는 이유 : **고칠 파일이 다르다.** 3 이면 데이터를 아무리 봐도 소용없다.

`--json` 은 모든 명령이 받는다 (AI 가 부르기 좋게).

```json
{"ok":false,"exit":2,"errors":[{"file":"GameData/drop.json","line":12,"table":"drop","row":"drop_boss_1","column":"itemId","rule":"ref","message":"item 에 'sword_irn' 이 없다"}],"counts":{"tables":3,"rows":412,"errors":1}}
```

## 6. 검증 규칙

| # | 규칙 | 걸리는 예 |
| --- | --- | --- |
| V1 | 유효한 JSON 배열인가 | 쉼표 빠짐 → 종료 4 |
| V2 | 모르는 열 / 필수 열 빠짐 | 스키마에 없는 `atkk` |
| V3 | 타입이 맞나 | `"atk":"12"` |
| V4 | `min`·`max` 안인가 | `"rate":1.4` |
| V5 | `enum` 값이 목록 안인가 | `"grade":"legend"` |
| V6 | `ref` 가 가리키는 id 가 **정말 있나** | `"itemId":"sword_irn"` |
| V7 | id 가 유일한가 · 꼴이 맞나 | 같은 id 두 줄 |
| V8 | 파일 이름 = 표 이름 · 스키마에 없는 표 파일 | `items.json` |
| V9 | `list<T>` 안 원소 타입 | `"tags":[1,2]` |

오류 한 건은 한 줄, 꼴은 `파일:줄: 표.열 — 무엇이 잘못됐나` 다.

```
GameData/drop.json:12: drop.itemId — item 에 'sword_irn' 이 없다 (가장 가까운 것: 'sword_iron')
GameData/item.json:37: item.atk — int 가 와야 하는데 문자열 "12" 다
GameData/item.json:41: item.id — 'potion_hp' 가 이미 3번째 줄에 있다
```

- **줄 번호를 꼭 낸다.** 「한 줄 한 행」이 여기서 값을 한다 — 줄 번호가 곧 행 번호다.
- `ref` 가 깨지면 **가장 가까운 id 를 같이** 보여준다(대부분 오타다). 편집 거리 2까지만 본다.
- **첫 오류에서 안 멈춘다.** 표마다 최대 100건 모아 한 번에 낸다. 넘으면 「…외 N건」으로 자른다 —
  스키마를 바꾼 직후 수천 줄이 쏟아지는 것을 막는다.

## 7. 내보내기 (`export`)

```
[0..3]   매직 "OFDT"
[4]      형식판 (uint8, 지금 1)
[5]      플래그 (uint8) — bit0 암호화 · bit1 압축 · 나머지 예약. 1차에는 0
[6..7]   예약 (uint16, 0)
[8..11]  본문 길이 (uint32, 리틀엔디안)
[12..15] 예약 (2차에 nonce 자리/길이)
[16..]   본문 — MessagePack
```

머리가 **16바이트 고정**이라 2차에 암호화를 켜도 게임 코드가 읽는 자리가 안 움직인다.
플래그가 0 이면 본문을 그대로, bit0 이 서면 `[16..]` 이 암호문이다.

본문은 MessagePack **맵 하나**다.

```
{ "_meta": {"schemaHash":"<sha256 앞 16자>","builtAt":"2026-09-18T21:00:00Z"},
  "item":  [ ["sword_iron","철검",12,"common",["weapon","melee"]], … ],
  "drop":  [ … ] }
```

- **행은 맵이 아니라 배열이다.** 열 이름을 행마다 되풀이하지 않아 파일이 훨씬 작고,
  MessagePack-CSharp 의 `[Key(n)]` 정수 키 계약과 그대로 맞물린다. n = 스키마의 열 차례다.
- `schemaHash` 는 스키마 파일의 해시다. 게임이 뜰 때 **생성된 C# 이 아는 해시와 다르면 바로 소리친다.**
  「스키마만 고치고 굽는 걸 깜빡한」 사고가 가장 흔하고 가장 조용하다.
- 표마다 파일을 쪼개는 길은 열어 두되 **1차는 한 장**이다 (쪼개면 Addressables 로 옮기기 쉬워진다).

### 7-1. MessagePack 을 어떻게 쓸까

| 안 | 별 · 라이선스 · 최근 푸시 (2026-09-18 GitHub API) | 판단 |
| --- | --- | --- |
| **직접 쓴다** (`internal/mpack`) | — | **민다** |
| `shamaton/msgpack` | 183 · MIT · 2026-09-13 | 살아 있고 MIT. 다만 별이 적어 사실상 1인 프로젝트다 |
| `vmihailenco/msgpack` | 2,676 · BSD-2 · **2024-06-04** | 가장 많이 쓰이지만 **2년 3개월 멈춰 있다** |
| `tinylib/msgp` | 1,950 · MIT · 2026-08-31 | 코드 생성기라 결이 다르다. 우리 값은 스키마가 정하므로 안 맞는다 |

직접 쓰자고 보는 이유 셋. ① 우리는 **내보내기만 한다** — 읽는 것은 C# 이고 Go 는 시험에서만 되읽는다.
② 내보내는 꼴이 **일곱뿐**이다(맵·배열·정수·float32·bool·문자열·nil) — 규격에서 이 일곱에 필요한 건 200줄 안팎이다.
③ 이 저장소의 다른 Go 툴이 전부 **바깥 라이브러리 0개**다. 그 결을 지키면 go.mod 를 영영 안 봐도 된다.

**부딪히는 점을 솔직히 적는다** : 직렬화기를 손으로 쓰면 **조용히 틀릴 수 있다.** 특히 정수 폭 고르기와
문자열 길이 머리가 그렇다. 막는 방법은 하나 — **C# 쪽 MessagePack-CSharp 로 되읽는 왕복 시험**(11장 U2)이다.
그게 안 되면 라이브러리로 간다. **→ 이 판단은 「메인이 정할 것」에 남긴다.**

## 8. C# 코드 생성 (`gen`)

만드는 파일 넷 : `<표>Row.cs` · `<enum>.cs` · `GameDataTables.cs`(통 + `Load`) ·
`GameDataIds.cs`(표마다 id 상수 — 오타를 컴파일 때 잡는다).

```csharp
// <auto-generated> datatool gen 이 만든 파일이다. 손대지 마라. 다음 gen 에서 덮인다.
// 원본 : GameData/schema.json (hash 4f2a…)
[MessagePackObject]
public sealed class ItemRow
{
    [Key(0)] public string Id { get; set; }
    [Key(1)] public string Name { get; set; }
    [Key(2)] public int Atk { get; set; }
    [Key(3)] public string GradeName { get; set; }   // enum 은 이름 문자열로 구워진다
    [IgnoreMember] public Grade Grade { get { … } }   // 읽을 때 쓰는 속성
    [Key(4)] public string[] Tags { get; set; }
}

public sealed class GameDataTables
{
    public IReadOnlyDictionary<string, ItemRow> Item { get; private set; }
    public const string SchemaHash = "4f2a…";       // gen 이 박는다
    public static GameDataTables Load(byte[] raw);   // 머리 검사 → 역직렬화 → 딕셔너리
}
```

- 이름 : 열 `atk` → `Atk`, 표 `item` → `ItemRow`. `snake_case` 는 `PascalCase` 로 붙인다.
- `enum` 열은 **이름 문자열 + `[IgnoreMember]` 읽기 속성** 둘로 낸다 **(구현 2026-09-18 반영)**.
  `[Key(n)]` 을 받는 것은 `GradeName`(string)이고, `Grade`(enum)는 그 문자열을 옮겨 주는
  `[IgnoreMember]` 속성이다. 구운 파일에 enum 이 이름 문자열로 들어가기 때문이고,
  **기본 리졸버가 enum 을 int 로 읽어 버리는 것과 IL2CPP 리플렉션을 같이 피하려는 것**이다.
  `ref` 열은 `string` 으로 낸다 (실제 객체는 로더가 이어 준다).
- `Load` 가 하는 검사 넷 : 매직이 `OFDT` 인가 · 형식판을 아는가 · 모르는 플래그 비트가 섰나 ·
  `_meta.schemaHash` 가 `SchemaHash` 와 같은가. 하나라도 어긋나면 **바로 예외**다.
  조용히 반쯤 읽는 것이 제일 나쁘다.
- **머리를 읽는 `GameDataLoader.cs` 는 생성물이 아니라** `DataTool/Unity/` 에 손으로 쓴 것이다.
  암호화가 붙는 자리가 여기라, 2차에 이 파일만 고치면 생성 코드는 안 건드린다.
  **(구현 2026-09-18 반영)** 다만 **사람이 복사하지 않는다** — `gen` 이 `go:embed` 로 품고 있다가
  네임스페이스를 갈아 끼워 생성 폴더에 같이 써 낸다 (`GameDataException.cs`·asmdef 도 같이).
  asmdef 는 파일 이름이 곧 어셈블리 이름이라 `<namespace>.asmdef` 로 나간다.

**네임스페이스 치환**은 CodeTool 복사 템플릿과 같은 방식이다 — `Officina.` 를 `<namespace>.` 로 바꾼다.
치환할 자리는 **`Unity/` 의 손으로 쓴 셋**이다(생성 파일은 `schema.json` 의 `namespace` 값을 박고 태어난다).
치환 뒤 **`Officina.` 잔여 0** 을 세고 0 이 아니면 파일·줄을 알리고 멈춘다.
**치환을 `gen` 안에 넣은 까닭이 이것이다 (구현 2026-09-18 반영)** — 사람이 손으로 옮기면 잔여를 아무도 안 센다.

**덮어쓰기** : 생성 폴더 안의 `.cs` 는 전부 덮는다(그래서 폴더를 따로 가른다). 그 폴더 밖엔 한 글자도 안 쓴다.
**지우지는 않는다** — 스키마에서 표를 없앴을 때 남는 `.cs` 는 목록으로 알리기만 하고 사람이 지운다.

## 9. 웹 표 UI (`serve`)

| 후보 | 별 · 라이선스 · 최근 푸시 | 판단 |
| --- | --- | --- |
| **Tabulator** (`tabulator-tables/tabulator`) | 7,768 · **MIT** · 2026-09-15 | **고른다** |
| RevoGrid | 3,444 · MIT · 2026-09-16 | 가볍지만 웹 컴포넌트라 껍데기가 한 겹 더 붙는다 |
| Glide Data Grid | 5,340 · MIT · **2026-01-21** | **React + 번들러가 필요하다.** 8개월째 조용하다 |
| Handsontable | 상용 | 값을 안 쓴다 — 탈락 |

**결정타는 「빌드 단계가 없다」**는 것이다. `.js` 한 장과 `.css` 한 장을 `ui/vendor/` 에 두고 `go:embed` 하면 끝이라
**npm · node_modules · 번들러가 이 저장소에 안 들어온다.**
조사 문서의 「Tabulator 별 수 조회 실패」는 풀렸다 — 저장소가 `olifolkerd/` 에서 `tabulator-tables/` 로 옮겨 갔다.

```
datatool serve [--port 0] [--open]
```

**(구현 2026-09-18 반영)** 옵션 이름이 뒤집혔다 — `--no-open` 이 아니라 `--open` 이다.
**기본은 브라우저를 안 연다.** 안 여는 쪽이 기본이어야 스크립트·CI 에서 부를 때 놀랄 일이 없고,
열고 싶은 사람만 한 글자를 더 치면 된다.

- **`127.0.0.1` 에만 붙는다.** `--port` 를 안 주면(= 0) 빈 포트를 받는다.
  프로세스가 사는 동안만 산다 — 상주하지 않는다.
- 뜰 때 **토큰을 한 번 뽑아** `http://127.0.0.1:<포트>/?t=<토큰>` 을 한 줄 찍는다 (`--open` 이면 브라우저도 연다).
  모든 API 가 이 토큰을 본다 — 13장 미결 5번을 **넣는 쪽으로 정했다**.

| API | 하는 일 |
| --- | --- |
| `GET /api/schema` · `GET /api/table/{이름}` | 스키마 전체 / 행 배열 |
| `PUT /api/table/{이름}` | **행 배열 전체**를 받아 검증 → 통과하면 파일을 다시 쓴다 (tmp → 이름 바꾸기) |
| `POST /api/validate` | CLI 의 `validate` 와 같은 일. 한 글자도 안 쓴다 |
| ~~`POST /api/export` · `/api/gen`~~ | **1차에는 안 만든다 (구현 2026-09-18 반영)** — 굽기·생성은 CLI 로 한다. UI 에서 부를 자리가 아직 없고, 쓰는 API 를 늘리면 막을 자리도 같이 는다 |

**UI 는 JSON 파일을 만들지 않는다.** 행 배열만 보내고 「한 줄 한 행 · 열 차례 · 기본값 빼기」는
**엔진의 `table` 묶음 한 곳에서만** 일어난다. 쓰기 규칙이 둘로 갈리면 UI 로 저장한 파일과 `fmt` 로 정리한 파일이
서로 다른 diff 를 낸다.

되돌리기·여러 칸 붙여넣기·정렬·거르기는 **Tabulator 몫**이다. 직접 만들지 않는다. 1차에 볼 것은 넷뿐이다.
① 2,000행 스크롤이 버벅이지 않는가 ② 엑셀에서 복사한 여러 칸을 붙여넣는가
③ `enum` 이 드롭다운, `ref` 가 **다른 표의 id 드롭다운**으로 뜨는가
④ **저장했을 때 git diff 가 고친 줄만 나오는가** ← 이게 설계 전체의 합격선이다.

## 10. 2차에 비워 둔 자리

| 무엇 | 비워 둔 자리 |
| --- | --- |
| 암호화 | 머리 `[5]` 플래그 **bit0**, `[12..15]` 예약 4바이트(nonce), `[6..7]` 예약 2바이트 |
| 압축 | 같은 플래그 **bit1**. 차례는 **압축 → 암호화** (조사 C장) |
| 키 | `datatool export --key-file <경로>` — **이름만** 정해 둔다. 1차에는 안 받는다 |
| 엑셀 가져오기 | `datatool import --xlsx <파일> --table <이름>` — 가져오기는 늘 `fmt` 를 거쳐 쓴다 |
| 다국어 | 스키마의 `"loc": true` (1차는 무시) · 명령 이름은 `datatool loc-export` |
| 표 쪼개 굽기 | `export --split` (Addressables 로 옮길 때) |

**1차에서는 위 자리에 대응하는 코드를 미리 안 짠다.** 플래그 비트와 명령 이름만 잡아 둔다 — 안 쓰는 코드는 썩는다.

## 13. 안 한 것 · 메인이 정할 것 · 위험

**안 한 것** — 코드를 한 줄도 안 썼다. Go 를 안 돌리고 Unity 를 안 열었다. **성능을 안 쟀다**
(「2,000행」·「수만 행」은 어림이다). Tabulator 를 실제로 안 띄워 봤다.
MessagePack-CSharp 가 **맵 안의 배열 행**을 어떤 어트리뷰트 조합으로 읽는지 코드로 확인 안 했다.
CastleDB 공식 사이트(`castledb.org`)는 접속이 막혀 저장소·2차 글로만 봤다.

**메인이 정할 것**

| # | 물음 | 갈림 |
| --- | --- | --- |
| 1 | **MessagePack 을 직접 쓸까, 라이브러리를 들일까** | 직접 = 의존성 0, 대신 조용히 틀릴 수 있다(T5·U2 가 막는다) / `shamaton/msgpack`(MIT·활발·별 183) |
| 2 | 소단계 차례 — 1→10 이냐 **위험 먼저**냐 | 뒤쪽이 U2 실패를 일찍 만난다 |
| 3 | `GameData/` 를 `Assets/` 밖에 둘까 | 밖 = `.meta` 가 안 붙는다 / 안 = Unity 에서 바로 보인다 |
| 4 | `GameDataIds.cs` 를 1차에 낼까 | 표가 크면 파일이 길어진다. 값은 오타를 컴파일 때 잡는 것 |
| 5 | `serve` 토큰을 1차에 넣을까 | **넣음 (구현 2026-09-18 반영)** — 같은 기계의 딴 프로그램을 막는 값이 코드 한 줄보다 크다 |
| 6 | 스키마를 **B안(표마다 파일)** 으로 갈까 | 지금은 C안. 표가 스무 개를 넘으면 다시 본다 |

**위험**

| 위험 | 어떻게 되나 | 막는 법 |
| --- | --- | --- |
