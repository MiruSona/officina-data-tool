## 0. 결론 먼저

- **U1~U6 을 사람 대신 스크립트 둘이 판정한다.** Unity 쪽은 `Unity/Verify/verify.ps1 -Project <경로>`, 웹 쪽은 `Test/u6/run.ps1`.
  둘 다 마지막에 판정 표를 찍고 종료 코드(0 통과 · 1 실패 · 2 환경 문제)로 끝난다.
- **DataTool 고침 넷** — ① 생성 `Deserialize` 가 `_meta` 를 읽은 그 자리에서 해시를 보고, 표가 `_meta` 보다 먼저 오면 바로 던진다.
  ② `table.canonical` 이 숫자를 **JS `String(Number)` 와 똑같은 꼴**로 적는다 → `fmt` 와 웹 UI 의 diff 가 갈리지 않는다.
  ③ 붙여넣기의 CRLF·끝 줄바꿈을 풀고, 표 끝을 넘친 행은 **알린다**(행을 안 늘린다). ④ Ctrl+S 가 열린 편집 칸을 먼저 확정하고, fetch 실패를 빨간 토스트로 알린다.
- **두 갈래로 나눠 같이 돈다.** 갈래 A = Unity 쪽(Verify·gen·Unity README·설계 13장), 갈래 B = 웹 쪽(ui·table·Test/u6). 겹치는 파일은 `README.md` 하나이고 줄 더하기만 한다.
- **범위를 하나 넓혔다** — U6 의 「범위 지우기」 시나리오가 통과하려면 웹 조사 4장 후보 8번(여러 행 지우기)이 있어야 해서 이번 판에 넣었다. 다음 판으로 넘기는 후보는 12건이다(9장).

## 4. 해시 비교 앞당김 (생성 `Deserialize`)

**확인한 사실** — 표 이름은 `^[a-z][a-z0-9_]*$`(`schema/parse.go`)이고 `mpack.Encode` 는 맵 키를 `sort.Strings` 로 쓴다.
`_`(0x5F)는 `a`(0x61)보다 앞이라 **Go 가 구운 파일은 `_meta` 가 늘 첫 키다.** 그러니 「표가 `_meta` 보다 먼저 오면 던짐」은 우리 파일엔 안 걸리고, 다른 길로 만든 파일만 막는다.

```csharp
// 전 — 표를 다 읽은 뒤에 본다. 열 꼴이 바뀌면 MessagePack 예외가 먼저 난다
case "_meta": ReadMeta(ref reader, out schemaHash, out builtAt); break;
case "item":  itemRows = MessagePackSerializer.Deserialize<ItemRow[]>(ref reader, options); break;
...
if (schemaHash != SchemaHash) throw new GameDataException("스키마가 달라졌는데 안 구웠다 …");

// 후 — _meta 자리에서 바로, 표는 _meta 를 본 뒤에만, 표 읽기 예외도 우리 예외로
case "_meta":
    ReadMeta(ref reader, out schemaHash, out builtAt);
    CheckHash(schemaHash);            // 다르면 여기서 GameDataException
    metaSeen = true;
    break;
case "item":
    RequireMeta(metaSeen, "item");    // "_meta 가 표보다 뒤에 있다 — datatool export 로 다시 구워라"
    itemRows = ReadTable<ItemRow>(ref reader, options, "item");   // MessagePackSerializationException → GameDataException(표 이름, inner)
    break;
default: reader.Skip(); break;         // 모르는 키는 _meta 앞이어도 건너뛴다 (앞으로 늘 수 있는 머리 칸)
...
CheckHash(schemaHash);                 // 끝 검사 — _meta 가 아예 없으면 "없음" 으로 던진다
```

- `CheckHash`·`RequireMeta`·`ReadTable<T>` 는 도우미 토막(`gen.go` 의 다섯째 토막)에 한 번씩 낸다. 메시지 문구는 지금 것을 그대로 쓴다.
- **고칠 것** : `internal/gen/gen.go` `tablesDeserialize`·도우미 · `Testdata/gen/expected/GameDataTables.cs` 다시 뽑기 · `gen_test.go` 에 「`CheckHash` 가 표 case 보다 앞」 문자열 검사 한 건.
- **`roundtrip-cs` 영향** : `../gen/expected/*.cs` 를 그대로 컴파일하므로 정답지가 바뀌면 같이 바뀐다. 코드 수정은 없고, `dotnet run` 57건 + 해시 어긋난 파일 1건을 **다시 돌려 통과를 본다.**

## 5. 숫자 철자 규칙

**규칙 한 줄 : 숫자는 float64 로 읽어 ECMAScript `Number::toString` 꼴로 적는다.** 브라우저가 `JSON.stringify` 로 보내는 꼴과 글자까지 같다.
열 타입은 안 본다(`canonical` 은 열을 모른다 — 지금도 그렇다). 값이 같으면 철자만 바뀐다.

만드는 법 (Go) — `strconv.FormatFloat(v, 'e', -1, 64)` 로 최단 숫자열 `s`(k 자리)와 지수를 얻고, n = 지수 + 1 로 둔다.

| 조건 | 꼴 | 예 |
| --- | --- | --- |
| k ≤ n ≤ 21 | `s` + (n−k)개 `0` | `300` |
| 0 < n ≤ 21 | `s` 앞 n 자리 `.` 나머지 | `12.5` |
| −6 < n ≤ 0 | `0.` + (−n)개 `0` + `s` | `0.000001` |
| 그 밖, k = 1 | `s` `e` 부호 \|n−1\| | `1e+21` · `1e-7` |
| 그 밖 | `s[0]` `.` `s[1:]` `e` 부호 \|n−1\| | `1.5e-10` |

`-0` 은 `0`. 부호 `+` 는 지수에만 붙는다(JS 와 같다). Go 의 `'g',-1` 은 `1e+20`·`1e-05` 처럼 경계가 달라 **쓰지 않는다.**
`1e999` 처럼 float64 를 넘으면 `canonical` 이 오류(「수가 float64 범위를 넘었다」)를 내고 `fmt` 는 그 파일:줄을 알리며 멈춘다. `NaN`·`Infinity` 는 JSON 이 아니라 읽기에서 먼저 막힌다.

| # | 적힌 것 | 나오는 것 | 볼 점 |
| --- | --- | --- | --- |
| 1 | `0` | `0` | |
| 2 | `-0` · `-0.0` | `0` | JS `String(-0)` |
| 3 | `1` | `1` | |
| 4 | `300.0` | `300` | **`fmt --check` 가 이제 종료 2** (F1 의 뿌리) |
| 5 | `1.25e1` · `1.25E1` | `12.5` | |
| 6 | `0.05` · `0.050` | `0.05` | |
| 7 | `1e21` | `1e+21` | 고정 표기 끝(n = 22) |
| 8 | `1e20` | `100000000000000000000` | n = 21 은 고정 |
| 9 | `1e-7` | `1e-7` | n = −6 은 지수 |
| 10 | `0.000001` | `0.000001` | n = −5 는 고정 |
| 11 | `123456789012345680000` | `123456789012345680000` | Go `'g'` 는 `1.2345678901234568e+20` |
| 12 | `0.30000000000000004` | `0.30000000000000004` | 0.1+0.2 꼴 — 최단이 17자리 |

- **고칠 것** : `internal/table/format.go` `canonical` — 디코드한 값 나무를 돌며 `json.Number` 를 위 꼴로 바꾼 뒤 인코드. `table_test.go` 에 위 표를 그대로 표 시험으로.
- **JS 와 정말 같은지** 는 U6 의 N1(7장)이 본다 — 위 값들이 든 표를 `fmt` 하고 UI 로 안 고친 채 저장해 diff 0.
- 기존 데이터 파일에는 `fmt` 를 한 번 돌릴 때 이런 줄이 한꺼번에 바뀐다 (승인됨). README 「데이터 꼴」에 규칙 한 줄을 더한다.

## 6. 붙여넣기 · 웹 수정의 UI 동작

**붙여넣기** (`ui/app.js`, `clipboardPasteParser` 를 우리 함수로 감싼다)

1. `\r\n` 과 홀로 선 `\r` 을 `\n` 으로 바꾼다.
2. **끝 줄바꿈 하나만** 뗀다 — 엑셀이 붙이는 것이 하나다. 둘 이상이면 나머지는 사용자가 고른 빈 행으로 본다.
3. 그 뒤는 Tabulator 기본 `range` 파서에 넘긴다 (감싸는 길은 구현 때 소스로 확인 — 9장 모르는 것 1).
4. **넘친 행은 알린다, 행을 늘리지 않는다.** 붙일 행 수 > (선택 맨 위 행부터 표 끝까지 행 수) 면 들어가는 만큼만 붙이고
   빨간 토스트 「붙인 N행 중 M행이 표 끝을 넘어 버렸다 — 행 추가 뒤 다시 붙여라」.
   **까닭** : 새 행에는 id 가 필요한데 붙인 칸에 id 열이 없으면 지어내야 한다. 행 수가 말없이 늘면 git diff 를 읽는 사람이 놀란다.
   「UI 는 값을 고쳐 주지 않는다」와도 맞다. 알림은 지금(말없이 버림)보다 확실히 낫고 크기도 S 다.
- 칸 안에 줄바꿈이 든 엑셀 따옴표 칸(`"a\nb"`)은 안 푼다 — 지금도 못 풀고, 게임 데이터 문자열엔 드물다 (위험 표).

| 수정 | 동작 |
| --- | --- |
| 편집 칸 연 채 Ctrl+S | `save()` 첫머리에서 `document.activeElement` 가 표 안 편집기면 `blur()` → 다음 프레임까지 기다린 뒤 `getData()`. 입력이 반영된 채 저장되고 dirty 가 꺼진다 |
| 저장 실패(fetch 예외) | `api()` 가 fetch 를 `try` 로 감싸 `{status:0, body:{ok:false, error:"서버에 못 닿았다 — datatool serve 가 꺼졌는지 본다. 고친 것은 화면에 남아 있다"}}` 를 돌려준다. `save()` 의 기존 실패 길이 빨간 토스트를 띄우고 dirty 를 그대로 둔다. 모든 API 호출에 같이 걸린다 |
| 여러 행 지우기 | 「행 지우기」가 **범위 선택이 있으면 그 범위의 행 전부**, 없으면 지금처럼 마지막으로 누른 한 행. 확인 대화상자 없음 — 토스트 「N행을 지웠다 — Ctrl+Z, 저장 전엔 파일이 안 바뀐다」(지금 문구와 같은 결) |

## 11. 위험

| 위험 | 어떻게 되나 | 막는 법 |
| --- | --- | --- |
| OfficinaTest 템플릿 패키지가 같은 이름 dll(`System.Collections.Immutable` 등)을 이미 들고 있다 | 「같은 어셈블리 둘」 컴파일 오류 | 5단계가 U1 실패로 잡는다. 그때 그 dll 만 빼는 스위치를 단다 |
| `.ps1` 을 BOM 없이 저장 | PowerShell 5.1 이 한글을 깨 읽어 스크립트가 터진다 | UTF-8 BOM 으로 저장 · 첫 실측에서 확인 |
| 십진 → float64 → 최단 → float32 두 번 반올림 | 아주 드문 값에서 구운 float32 가 1ulp 어긋날 수 있다 | 같은 float64 면 거의 늘 같다. 실데이터 export 전후 바이트 대조를 C1 에서 한 번 |
| 2^53 넘는 정수 철자 | `fmt` 가 값을 바꿔 적는다 (UI 와 같다) | int 는 32비트 범위 검사, float 는 32비트라 어차피 못 담는다 — 받아들인다 |
| 숫자 정규화가 기존 데이터에 한 번 큰 diff | 리뷰가 무거워진다 | 승인됨. 게임 저장소엔 `fmt` 만 한 커밋으로 따로 |
| 실제 엑셀 클립보드가 P1 과 다르다 | 붙이기 고침이 덜 맞는다 | 사람 손 한 번 남는다 (OS 클립보드는 CDP 로 못 봄) |
| 실제 게임 프로젝트 IL2CPP 빌드가 길다 | 7단계 이전 시간 넘김 | 빌드엔 제한을 안 두고 플레이어만 60초 |

**모르는 것** — 1) Tabulator 6.5.3 의 기본 `range` 파서를 감싸 부르는 정확한 길(`extendModule` 등)은 소스를 열어 정한다. 막히면 붙이기 이벤트를 앞서 잡아 고친 글로 `paste` 를 다시 부른다.
2) 리스트 편집기(`list`)가 `blur()` 에 값을 확정하는지 — S7 은 input·number 로만 본다. 3) OfficinaTest 에 `test-framework` 가 이미 있다는 조사 기록을 믿었다(0단계에서 manifest 를 본다).
