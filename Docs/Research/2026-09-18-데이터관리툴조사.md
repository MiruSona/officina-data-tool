# 데이터 관리 툴 조사 — 세 갈래 묶음 (2026-09-18)

게임 데이터(스탯·아이템·드롭 테이블)를 **표로 보고 고치고 → Unity 로 내보내고 → 암호화**하는 툴을
만들기 전에, 세 갈래로 나눠 조사했다. 전부 웹 조사이고 아무것도 만들어 보지 않았다.
이 문서는 **결론과 판단만** 모은다. 근거와 표는 아래 세 문서에 있다.

## 1. 무엇을 조사했나

| --- | --- | --- |

| `DataTool/Docs/Research/2026-09-18-데이터툴-저장형식과암호화조사.md` | 어디에 담고 어떻게 잠글까 | 원본은 git 친화 JSON, 굽는 건 MemoryPack, 그 위에 압축 → AES-256-GCM |
| `DataTool/Docs/Research/2026-09-18-데이터툴-기성품조사.md` | 이미 있는 것 | 표 편집기·코드 생성은 기성품이 충분하다. **암호화만 어디에도 없다** |

## 2. 세 갈래가 수렴한 결론

| 무엇 | 정한 것 | 왜 |
| --- | --- | --- |
| **툴 형태** | **엔진(CLI)과 표 UI 를 가른다.** 엔진은 Go 단일 실행 파일, 표 UI 는 직접 만들지 않고 **웹 그리드 라이브러리(MIT 계열)** 를 `go:embed` 로 얹는다 | 기존 툴들과 같은 결이라 배포가 공짜다. 엔진이 CLI 라 AI 가 그대로 부른다. **언어 자체는 갈림길이 아니다** — 가장 비싼 건 표 UI 고, 그건 남의 것을 쓴다 |
| **원본 저장** | **JSON, 테이블별 한 파일 · 한 줄 한 행.** 스키마는 **C# 코드**에 둔다. **서버 DB 는 안 쓴다** | git 이 줄 단위로 diff·merge 하고 AI 가 그냥 읽는다. 서버 DB 는 1인에게 과하고 git 밖으로 나간다 |
| **엑셀·구글 시트** | 원본이 아니라 **「들어오는 문」** | 밸런스 수식은 시트에서 짜는 게 편하다. 다만 커밋되는 원본은 JSON 이다 |
| **런타임 형식** | **MemoryPack 바이너리** 한 덩어리 (2순위 MessagePack) | 소스 제너레이터라 IL2CPP 에서 안전하다. 결과가 바이트 배열 하나라 암호화가 그냥 붙는다 |
| **암호화** | **압축 → AES-256-GCM.** 헤더에 버전·nonce 를 박고, 키는 **코드 상수부터** 시작. **데이터 파일만** 감싸고 에셋번들은 안 건드린다 | 목표는 「막기」가 아니라 **「메모장 치트·데이터 긁기를 귀찮게 하기」**다. 키가 클라이언트에 있는 한 작정하면 뚫린다 — 그 이상은 값이 급격히 비싸진다 |
| **기성품** | 표 편집기·코드 생성은 기성품(Charon·Luban·CastleDB)이 충분히 좋다. **암호화만 어느 툴에도 없다.** 설계 전에 **Charon 을 한 번 써 보고 CastleDB 화면 구성을 본보기로 삼는다** | 바퀴를 다시 깎지 않기 위해서다. 우리 자리가 어디인지 먼저 눈으로 본다 |

## 3. 세 갈래가 어긋난 자리

| 갈래 | 주장 | 이유 |
| --- | --- | --- |
| 구현언어 | **엑셀 편집기 + Go 변환기부터** 만들자 | 표 편집기 만드는 공수가 0 이다. 인디 현장에서 가장 흔한 길이다 |
| 저장형식 | 엑셀은 원본이 아니라 **「들어오는 문」**이다 | xlsx 는 diff·merge 가 안 되고 AI 가 못 연다 |
| 기성품 | **Charon/Luban 을 먼저 써 보자** | Charon 이 무료로 요구의 8할을 덮는다 |

**메인 판단** — 사용자가 「툴을 만들 것」이라고 했으니 **직접 제작을 전제**한다.
그 위에서 ① 엑셀 가져오기는 **1차 범위 후보**로만 두고(없어도 돌아간다),
② 기성품은 **설계 전 30분 시험**만 한다(사서 쓰자는 게 아니라 화면·설계를 눈으로 보려는 것).

## 4. NC 툴의 정체 — 확정 못 함

사용자가 기억하는 「NC 가 만든 비슷한 프로그램」의 유력 후보는 **Crema** 다.

- 엔트리브소프트(NCSoft 자회사, 2024-02 문 닫음) 가 만들었다. **MIT · 2022 년에 멈춤.**
- WPF 화면 + **데이터를 SVN 에 저장** + **여러 사람 동시 편집** + 엑셀 주고받기 + C#·TS·C++ 코드 생성.
- 다른 후보는 NC 사내 **「게임 리소스 스튜디오」** — 공개 코드가 없어 생각만 빌릴 수 있다.

**확정하려면 사용자 확인이 필요하다.** 자세한 것은 기성품 조사 문서 (1) 절.

## 5. 사용자가 정할 것

1. **NC 툴이 Crema 가 맞나?** 맞다면 그 설계 문서를 더 팔 값어치가 있다.
2. **표 UI 를 직접 만드나(1안), 엑셀 편집 + 변환기로 가나(2안)?** 나머지가 다 여기서 갈린다.
3. **1차 범위에 암호화와 엑셀 가져오기를 넣나?** 둘 다 없어도 툴은 돈다.
4. **툴 이름** — `DataTool` 은 임시다.
5. **런타임 형식을 MemoryPack 으로 확정하나?** 속도(MemoryPack) vs 파일 크기·LZ4 내장(MessagePack).

## 6. 확인 못 한 것

- **`AesGcm` 이 Unity 6 IL2CPP 의 각 플랫폼(Windows/Android/iOS/WebGL)에서 실제로 도는지.**
  .NET 문서의 「`IsSupported` 로 확인하라」까지만 봤다. **빌드해 봐야 안다.** WebGL 이 특히 의심스럽다.
- **웹 그리드의 실제 UX** — 되돌리기·여러 칸 복사 붙여넣기가 어디까지 되는지는 **만들어 봐야 안다.**
  10만 행 벤치 수치도 그리드 제작사 쪽 글이라 중립이 아니다.
- **NDC·GDC 원문** — GDC Vault 는 유료 구간이라 제목·요약만 봤고, NDC Replay 는 검색으로 못 뚫었다.
- **Crema 가 그 툴인지** — 사용자 확인 전까지 미확정.
- **Charon 의 실제 사용감**과 무료(Personal) 판의 경계 — 설치해 보지 않았다.
- **Luban 이 암호화를 붙일 수 있는지** — 문서에 없다. 「템플릿으로 뒤처리」는 추측일 뿐이다.
- **TableForge 의 라이선스** — 저장소에 라이선스 파일이 없다. 쓰기 전 확인 필수.
- **BakingSheet 가 멈춘 이유**(2024-06 이후 커밋 없음) · **MemoryPack vs MessagePack 의 우리 데이터 실측** ·
  **수만 행 JSON 을 툴이 얼마나 빠르게 읽고 쓰는지** · **엑셀 xlsx 읽기 라이브러리의 라이선스·성능** — 전부 안 재 봤다.
